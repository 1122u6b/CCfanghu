## 本分支改动

- `LocalPipe.cs`：激活、恢复、导入出口、换码允许较长操作时间；操作超时后仍用新的写入期限向界面返回明确错误。
- `Runtime.cs`、`bridge.js`：激活时及时发布准备状态；激活后忽略较早发出的未激活状态回包；重开界面能够从账户状态恢复到主界面。
- `BrowserProbe.cs`、`Runtime.Product.cs`、`bridge.js`：浏览器实际 IP 和 WebRTC 回传同步更新检查行；缺失 IP 或尚未完成时保持未知，不能判为正常；出口变化时不使用旧出口证据；重开检查记录时一并刷新当前出口的浏览器区，防止旧快照覆盖最新两行。
- `Runtime.Product.cs`、`Runtime.Views.cs`：出口归属地与当前 IP 绑定；查询失败可重试，不缓存不完整地理信息；未取得时区时显示未查，不能假绿。
- `DownloadSample.cs`、`Runtime.Views.cs`、界面：真实下载采样，连接成功后采样最多 8 秒/512 KiB；到采样期限时允许有效的部分数据得出结果，零数据、外部取消、线路改变仍报错；按钮立即显示进度，完成后消费真实结果。
- `Runtime.cs`：远端出口探测与本地防护健康检查分开运行，慢请求不阻塞本地检查和界面操作；通过配置代次防止旧探测覆盖新线路结果；地理查询与线路采样并行。
- `EgressProbe.cs`：专用出口回访点发生传输故障时，可改用经同一本地代理发出的独立 HTTPS 公网 IP 查询；不发送设备凭据到公网查询服务。证书校验失败、鉴权/HTTP 错误、无效响应和外部取消不允许触发该降级。
- `bridge.js`、`ui.js`：有限期付费软件授权按后台实际时间显示，不能一律显示永久；概览、个人中心和到期提醒一致；单独软件的到期文案使用“授权”。
- `Installation.cs`：本机候选版本保留此前 `-local` 版本，方便现场回退。不是正式官网发布策略的最终决定。

## 本机实测结论

1. 全部旧 Leyra 安装和专用缓存清理后安装 local3；安装前确认无服务、无旧安装、无旧激活文件，首次启动为未激活。用后台新生成的未使用 1 天付费测试码完成首次激活，自动进入概览，重开仍保持激活。概览和个人中心正确显示 1 天及次日到期。
2. 之后单独备份新测试账户，恢复原账户和已保存出口，未退回旧版客户端。首次恢复辅助脚本曾因 Windows PowerShell 的 UTF-8 BOM 写入导致状态文件读取失败，自动回退成功；改为无 BOM 写入后恢复成功。这不是本分支修改了 `AgentStore` 的 JSON 编码兼容性。
3. Chrome、Edge、Firefox 都实际回传与客户端一致的住宅出口 IP，未报告其他 WebRTC 地址；对应两项状态实时更新。界面补丁重开后验证了检查记录重新打开也能恢复当前浏览器结果。
4. 深度检查观察一分钟，环境和防护组件正常，物理网卡直连公网及 DNS 被拒绝。出口归属 Los Angeles，系统时区为 Pacific Standard Time（UTC-08:00），时区比对通过。
5. 线路页测速按钮立即显示进度，实测下载约 0.2 Mbps。历史检查中的“尚未测速”仍是该次检查时的快照，不能误认为新测速结果丢失。
6. 22:24:30 至 22:39:32（约 902 秒），每 5 秒记录一次，共 181 次有效样本，全部为 protected，服务全部为 Running。该窗口内无新增错误日志。不是整夜、休眠唤醒、切网、重启或严格零流量测试。

### 添加/切换出口后的 DNS 验证超时

稳定观察结束后，22:41:03 和 22:41:21 的日志出现 `StartProtected -> VerifyDns` 的 `OperationCanceledException`，继而触发出口切换或阻断。用户明确确认此前添加或切换了出口。因此不能宣称所有断线问题已经修完，也不能把这段算作前述稳定观察窗口内的自行掉线。

当前 `VerifyDns` 单次系统解析期限为 7 秒；建立链路包含私有 DNS、出口回访等步骤。需要区分 DNS 查询、权威检测回执、出口回访、用户再次切换和主动停止等失败阶段。建议先加不含凭据的分阶段诊断，再验证有界重试/期限设计；不能通过跳过 DNS 验证、假报 protected 或放开真实网络解决。

### 高延迟与本机直连 SOCKS5

实际链路为：应用 → TUN/Mihomo → 带 TLS 的自建前置 SOCKS5 → 服务端选择的住宅出口 → 网站。

界面“延迟”是经代理访问 `https://www.gstatic.com/generate_204` 的 URL 请求耗时，当前超时 3000 ms；“成功率”是该 URL 探测完成比例，不是 ICMP 丢包率。部分 3 秒以上仍能成功的请求会被算失败，提高阈值只能改测量口径，不能降低真实耗时。

分阶段测量：本地代理 TCP 连接约 1～3 ms，整条链路取得 HTTPS 响应约 2.3～4.3 秒。受控前置对照请求 4/4 成功，首字节约 2.7～4.6 秒，两次公网 IP 查询确认同一住宅出口。

用户提供的住宅 SOCKS5 在本机可建立 TCP（通常约 165～169 ms，另一次约 1170 ms），但 4 次均在 SOCKS 方法协商回复前被对端关闭，尚未进入账号密码认证。额外测试同时提供无认证/用户名密码方法、仅无认证，以及 TLS 握手，也未取得可用协商回复。不能断言是密码错误；来源 IP 白名单、网络路径拦截或入口协议问题都尚未排除。请先核对供应商入口和直连授权，然后再比较同一出口，不能把 TCP 建连时间当作网页延迟。

Mihomo 支持 SOCKS5 出站，但当前产品的节点下发、固定服务器身份、WFP 端点白名单、DNS 与出口验证绑定前置。要增加本机直连，需要协调修改，保留默认拒绝、认证失败/断线不回退真实网络。此功能尚未实现，当前没有把住宅出口改为本机直连。
